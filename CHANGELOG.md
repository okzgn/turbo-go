# Turbo changelog

[Español](CHANGELOG.es.md)

v2.4.1 is the next release after v2.4. If you upgrade from **v2.4**, read [Upgrading from v2.4](#upgrading-from-v24) first. If you upgrade from **v2.3.rc3**, every stage of v2.4 and of v2.4.1 applies: read [Upgrading from v2.3.rc3](#upgrading-from-v23rc3) first, and then [Upgrading from v2.4](#upgrading-from-v24).

Published binaries are static and built with the latest Go 1.26 patch. Check the download with `SHA256SUMS`, in the folder of the download: `sha256sum -c --ignore-missing SHA256SUMS` (`--ignore-missing` checks only the binaries you downloaded; without it, `sha256sum` fails for the others).

## Upgrading from v2.4

**Recommendation: upgrade as soon as possible.** v2.4.1 fixes security issues: a client could hold every CGI slot and leave the PHP of every site answering 503, a stolen panel session could change what the administrator later confirms with the password or reach the panel through an error template, and a site could lose its settings when its folder couldn't be read, its scripts then served as text. Details are in the repository's security advisory, published together with this version.

Before upgrading, back up the sites folder, `turbo.config` included, and review the breaking changes of v2.4.1, especially:
- the response templates and the character replacements need the current password, the actions that need it take their values as sent (an API client sends them URL-encoded, without the tokens of the replacements), and a replacement can't be for letters or digits;
- every error page carries a `Content-Security-Policy` without scripts, on every host;
- a new password has 12 to 64 bytes;
- changing the credentials, or closing every session, ends the session of the request too: the answer brings a new one, which an API client takes from its `ok` header; and a session lasts 12 hours at most;
- a `PA` with networks and no host lets the panel answer only on an IP address or `localhost`;
- `turbo.config` with a site that isn't a JSON object, or a whole one whose `M` names a directory that doesn't exist or can't be listed, is invalid: Turbo doesn't start with it;
- a site or subdomain that Turbo keeps without its folder can't be created again from the panel until it is deleted there, which deletes no folder;
- at most a quarter of the CGI slots may wait for the responses of one client (an IPv4 address or an IPv6 /64; half for a /48): a response that would wait beyond that is cut;
- the reference systemd unit restricts more what Turbo and its CGIs can do: reinstall it following its comments, and check that your CGIs still work.

The commit "v2.4." `57cbb3c` of `main` is v2.4; stage 6 (the third review) wasn't in it, and comes with v2.4.1.

## Upgrading from v2.3.rc3

**Recommendation: upgrade as soon as possible.** This version fixes security and stability issues: some could expose files outside a site, stop or hang the server, or affected the admin panel, certificates and the TLS configuration. Details are in the repository's security advisory, published together with this version.

Before upgrading:

1. **Back up the sites folder**, `turbo.config` included. Turbo also keeps an automatic copy (next point), but it does not cover certificates or site content.
2. **`turbo.config` changes format.** Turbo reads old files and converts them in memory. The first time you save the configuration from the panel, it keeps the original as `turbo.config.v1.bak`, with `0600` permissions, and writes the new format, marked with `"^": {"v": "2"}`.
3. **Going back to an earlier version is not transparent.** To do it, restore `turbo.config.v1.bak` as `turbo.config`. If you keep the new file:
   - the old version reads `CIL` and `CIS` as 10 ms units, so the intervals would be 10 times longer;
   - it ignores the saved password (`PH`) and falls back to `Admin` or `TURBO_PASSWORD`;
   - it tries indexes in random order;
   - it does not apply the panel restriction (`PA`).
4. **Give the panel a host of its own** in `PA`, one that serves no site (see the README, also for HTTPS on that host), and change the default credentials. v2.3.rc3 doesn't save the password in `turbo.config`: after the upgrade it is `Admin` again (or `TURBO_PASSWORD`) until you change it.
5. **Review the breaking changes** of each stage of v2.4, and then those of v2.4.1 ([Upgrading from v2.4](#upgrading-from-v24)), especially:
   - Turbo does not start if `turbo.config` is not valid JSON or can't be read, if its `PA`, `U` or `PH` can't be used, or if it only points to its own directory or to one it can't use, and says why;
   - a preprocessor of `turbo.config` that can't be used makes its extension answer 500;
   - changing the sites directory to one without `turbo.config` keeps the settings in use;
   - the panel logs in only by `POST /admin:`, and `PA` combines hosts and networks with AND;
   - rewrite sources are compared with the decoded path, and a source that ends in `/` also takes the folder without it;
   - a subdomain serves only its own host: deeper levels need a wildcard (`*.api`, or the site's `*`);
   - TLS 1.2 minimum;
   - Certbot no longer runs on its own;
   - the panel session moves to a cookie;
   - "Denied IP" now blocks;
   - the process exits if it cannot open port 80;
   - `addPreprocessor`, `delPreprocessor`, `hardUpload`, `delSite`, `cfgC a=0` and `cfgPC a=0` need the current password, and the panel over HTTP may answer with a redirection to HTTPS;
   - a `turbo.config` edited by hand is applied as a whole when it changes: what is no longer in the file stops applying, and changes made from the panel and not saved are lost;
   - rewrites whose target uses keywords: check that they still give the expected URL (the values are encoded for where they go);
   - sites named `turbo.dev`, `turbo.panel`, `turbo.certificates`, `turbo.config`, `turbo.visits` or `turbo.denials`, a site `c.a.b` together with the subdomain `c` of `a.b`, and an alias with the host of a site are refused: on loading, the one that loses is dropped with a warning, and the next save leaves it out of `turbo.config`, so check the log after the first start;
   - the per-IP limits and the failed-login block count each IPv6 /64 as one client, and at most `CGP` CGI processes run at once (by default 4 per CPU, at least 16; beyond, 503): raise `CII`/`CIS` or `CGP` if your traffic needs it;
   - the reference systemd unit runs without root, with the binary in `/usr/local/bin`: reinstall it following its comments.
   - the panel, the API messages and the logs are in English, `setC` confirms with `a=overwrite`, and the log lines have English keys: update any client or script that compares them.
   - a site whose folder is deleted stays in `turbo.config`, with its settings, until it is deleted from the panel or from the file.
   - CGIs no longer get the request headers with `_` in their name, `HTTP_HOST` is the host as it chose the site, and an IPv6 denied IP denies its /64.

**The commits "v2.3.rc4." (`9307623`) and "v2.4." (`808dc6f`) of `main` are not releases:** `9307623` has stages 1 to 3 of v2.4 and `808dc6f` stages 1 to 4; v2.4 is the commit "v2.4." `57cbb3c`, with stages 1 to 5. If you built Turbo from one of the first two, upgrade too; its `turbo.config` already has schema 2, so points 2 and 3 don't apply, and the breaking changes to review are those of the stages it lacks (4 and 5 from `9307623`, 5 from `808dc6f`) and those of v2.4.1.

## v2.4.1

The first release after v2.4. It brings the fixes of a review of Turbo for production and those of the third review of v2.4 (stage 6), which v2.4 didn't have: they are listed below, newest first, and both apply when upgrading from v2.4.

### Production review

#### New
- **Close every session:** **Close every session**, in **General settings** (`closeSessions` in the API), closes every session of the panel, also the copies of the token of the one that asks, and gives that one a new session. It needs the current password.
- **Sites without their folder in the panel:** the sites whose folder isn't there, which Turbo keeps with their settings for when it comes back, are listed in **Sites without their folder**, where Turbo can be told to forget them (no folder is deleted); the API's `sites` lists them under `~`. Turbo logs, when it reads `turbo.config`, each site it keeps without its folder.

#### Fixes
- **HTTP/2, a client that stops reading:** an HTTP/2 connection has a single writer. With a client that stopped reading, the write deadline of each response (`WT`) only queued a reset that couldn't be written, and every handler of the connection, with its CGI and its slot, waited for as long as the client kept it open: a few connections like that left the PHP of every site answering 503. Now a connection where nothing can be written for 30 s is closed, and so is one that doesn't answer a PING within 15 s after 60 s without a frame from the client.
- **HTTP/1, a client that reads slowly:** a CGI kept its slot until its client had read the whole output, up to `WT` + 2 s, however fast the script was: about one request per second from a single IP left the PHP of every site answering 503. Now the output of a CGI waits for its client in memory (up to 1 MiB per response and 64 MiB in all) and then in a temporary file (up to 256 MiB per response and 1 GiB in all, measured on disk), and the CGI frees its slot when it ends, also when its response is cut. A client (an IPv4 address or an IPv6 /64) may take a quarter of each of those totals, and a /48 half. Beyond those limits a CGI waits for its client, as before, but at most a quarter of the CGI slots may wait for the responses of one client (half for a /48): a response that would wait beyond that is cut, and its CGI ended.
- **Character replacements:** the session alone could add one (`s=php d=phtml`), and the server then read the token as the replaced text in every parameter of every action, also in those confirmed with the password: the administrator's `delPreprocessor a=phtml` deleted the preprocessor of `php` (its scripts were then served as text), a subdomain deleted could be another one, and `addPreprocessor` could save another program. Now adding or deleting a replacement needs the current password, a replacement can't be for letters or digits, and the replacements aren't undone in the actions that need the password nor in the site and the subdomain of any action.
- **Error templates:** with `PA` empty (the default), a response template with a script, which the session alone could set, ran it on the panel's origin, from where it could take the password the next time the administrator confirmed something. Now every error page carries a `Content-Security-Policy` without scripts, on every host, and adding or deleting a template needs the current password.
- **`turbo.config` read while a site's folder can't be read:** at the start, or when the file was read again, a site whose folder or `@` couldn't be looked at (permissions, I/O, a network disk) lost its settings, and when the folder could be read again the site came from the disk with the defaults, its scripts served as text. Now its settings are kept, as for a folder that isn't there, and apply when the folder can be used.
- **A malformed site in `turbo.config`:** a site, a subdomain or a list of one that isn't a JSON object (`"?": null`, `"?": "php"`, `"": null`) was skipped without a word, and the site was active without its preprocessors, its scripts served as text; and a preprocessor with a control character was dropped. Now the first makes the file invalid (Turbo doesn't start with it, a reload keeps the configuration in use, and the message points at the site), and the second answers 500, as a preprocessor that can't be used.
- **HTTPS of a site whose certificate can't be loaded yet:** an `"S": "1"` of `turbo.config` was lost when the certificate couldn't be loaded then (a copy that brings `@` before the `.pem` files, a key that can't be read yet), and the next save wrote `"S": "0"`. Now it is kept, there is no redirect without the certificate, and the certificate is loaded at the next look at the configuration (every 30 s).
- **Following `M`:** a whole `turbo.config` whose `M` named a directory that doesn't exist yet (a disk not mounted) was applied in the start directory, every site was left without its folder, and saving wrote that directory as `M`; one whose directory couldn't be listed, and a `setM` to a directory whose `turbo.config` led, through its own `M`, to one that can't be used, emptied the configuration in use before finding it out. Now the whole chain is checked before anything is applied (also an `"M"` written as a number, which the setting reads as the name of a directory): Turbo doesn't start, a reload keeps the configuration in use, and `setM` refuses it.
- **`turbo.config` dated at the Unix epoch:** Turbo took a file with that date (as some reproducible builds and image layers leave them) for one it had already read, and started with the defaults: the default credentials, the panel on any host and the sites without their settings. Now it knows `turbo.config` by its date and its size, and reads it at start whatever its date; a file rewritten with the same date and another size is read again too.
- **The `turbo.config` of the start directory and that of `M`, the same file:** when one is a symbolic link to the other, saving wrote the pointer over the whole configuration it had just saved, and Turbo didn't start again. Now it leaves it whole.
- **Sessions:** changing the username or the password kept the session of the request, so a copy of its token (a cookie taken from the same IP, behind the same NAT) survived the change, and a session renewed itself for as long as it was used. Now `setU`, `setP` and `setM` with other credentials close every session and give the one that asks a new one, and a session lasts 12 hours at most from its login.
- **Failed logins:** the limit counted each IPv4 address or IPv6 /64, and a /48 has 65 536 of them. Now the /64s of a /48 share a limit of 20 failures in 10 minutes. One of the password checks that run at a time is kept for the requests with a session and for the logins from the networks of `PA`, so a flood of logins from elsewhere doesn't keep the administrator out (503). A new password has 12 to 64 bytes.
- **`PA` with networks only:** the panel answered on any host, so a page whose name resolves to Turbo (DNS rebinding) could reach it from the browser of someone in those networks. Now, with networks and no host, the panel answers only on an IP address or `localhost`, and Turbo warns about it at startup.
- **Logs:** only the failed TLS handshakes were grouped. The other connection errors of the server (among them, one line for each GOAWAY frame with an error that an HTTP/2 client sends) and those of the CGIs whose client goes away went out one line each, which let anyone fill the log, and journald then dropped the real messages. Now they are grouped by kind: the first of each kind at once, and then at most one line a minute with the count and the last one, also when Turbo stops.
- **`release.sh`:** it published `SHA256SUMS` without `govulncheck` (it only warned), and it left the binaries without sums when it failed. Now it fails without `govulncheck` (unless `TURBO_RELEASE_WITHOUT_GOVULNCHECK=1`), checks that each binary was built from the tagged commit, without changes and without cgo, and removes `dist/<version>` when it doesn't end well.
- **The systemd unit:** it didn't limit what a compromised CGI could do on the host. Now it adds `UMask=0027`, `ProtectHome=tmpfs` with `BindPaths=/home/server`, `PrivateDevices`, the `Protect*` of the kernel, the control groups, the clock, the host name and `/proc`, `RestrictNamespaces`, `RestrictRealtime`, `RestrictSUIDSGID`, `LockPersonality`, `RestrictAddressFamilies`, `SystemCallArchitectures=native` and `SystemCallFilter=@system-service`, and `deploy/systemd-test.sh` checks them.
- **Continuous integration:** each job has a time limit, so a test that hangs ends with the stacks of its goroutines instead of at the 6 hours of GitHub, and the checkout doesn't keep the token.

#### Breaking changes
- **The current password for the response templates and the character replacements:** `addHttpCodeResponse`, `delHttpCodeResponse`, `addCharsReplace` and `delCharsReplace` need it in `b`; the panel asks for it.
- **What the server reads as sent:** the actions that need the current password, `cfg<KEY>` and `hardUpload` take their parameters as sent, and the site and the subdomain (`s`, `d`) of every action are never replaced. An API client that sent those values with the tokens of the replacements (`-.-` for `;`…) must send them URL-encoded, as an `application/x-www-form-urlencoded` body does. A replacement for letters or digits is refused, and one in `turbo.config` is dropped with a warning.
- **No scripts in any error page:** every error that Turbo answers with the error template carries a `Content-Security-Policy` without scripts, on every host: a template with scripts no longer runs them.
- **A new password has 12 to 64 bytes** (`setP`). One already in use keeps working; `TURBO_PASSWORD` with fewer than 12 bytes gets a warning, and with more than 64, or with control characters, Turbo doesn't start. A plain-text `P` written in `turbo.config` may have up to 64 bytes too (before, 24).
- **Sessions:** `setU`, `setP`, `setM` with other credentials and `closeSessions` end the session of the request too, and the answer brings the new one: the cookie, and the `ok` header, from which an API client must take it. A session ends 12 hours after its login.
- **`PA` with networks and no host** answers only on an IP address or `localhost`: to reach the panel by a name, add that name to `PA`.
- **`turbo.config`:** a site, or a list of a site, that isn't a JSON object, and a whole `turbo.config` whose `M` names a directory that doesn't exist or can't be listed, make the file invalid: Turbo doesn't start with it, and a reload keeps the configuration in use.
- **Failed logins:** the IPv6 /64s of a /48 share a limit of 20 in 10 minutes.
- **`sites`** lists the sites without their folder under `~`. A site or subdomain listed there can't be created from the panel (`addSite`, `addSubdomain`: 400) until `delSite` forgets it, which deletes no folder.
- **Logs:** the connection errors and those of the CGIs go out grouped by kind (the first at once, then at most one line a minute with the count): a tool that counted their lines must read the count.
- **The output of the CGIs:** at most a quarter of the CGI slots (half for an IPv6 /48) may wait for the responses of one client (an IPv4 address or an IPv6 /64), and a response that would wait beyond that is cut, its CGI ended; behind a proxy, all the clients are one.
- **The systemd unit** restricts what Turbo and its CGIs can do: no other home folder, devices, kernel settings, namespaces, other address families or system calls outside `@system-service`, and the files it creates are no longer readable by other users. Reinstall it following its comments (`/home/server` with `0750`), and check that your CGIs still work.
- **`release.sh`** needs `govulncheck`.

### Stage 6: third review

#### Fixes
- **A site whose folder disappears for a moment keeps its settings:** every 30 s Turbo deactivates the sites whose folder or `@` is no longer there, and when the folder came back (a deploy that deletes and recreates `@`, an upload by FTP, a network disk that didn't answer) the site was activated again with the defaults: without its preprocessors (its scripts were served as text, their source included), HTTPS, headers, rewrites or aliases, until Turbo was restarted or `turbo.config` was edited, and saving meanwhile wrote that into `turbo.config`. Now a deactivated site keeps its settings and gets them back with its folder, and saving keeps it in `turbo.config`. Only a folder that doesn't exist deactivates a site: another error of the disk (permissions, I/O, a network disk that doesn't answer) leaves it as it is, and a sites directory that can't be read deactivates none (before, it deactivated them all).
- **A site of `turbo.config` whose folder isn't there:** when `turbo.config` is read, its settings are kept (and saved) and apply when the folder appears; before, the site was left out without a word, and its folder, when it appeared, was a new site with the defaults.
- **A whole `turbo.config` whose `M` names another sites directory:** without a `turbo.config` there, it applies there, with its sites, which are those of that directory; before, it was applied and then emptied when following `M`, and every site was left with the defaults (its scripts served as text) at every start. With a `turbo.config` there that can't be used (invalid, or with pointers that lead back), Turbo doesn't start and a reload keeps the configuration in use, as with a pointer; before, the reload emptied it. The folders of the directory that `M` leaves are no longer activated as sites on the way.
- **Errors before the request is read, without scripts:** the errors that Turbo answers before reading a whole request (400 for a malformed request or for plain HTTP to the HTTPS port, 414, 431, 501), over HTTP/1 and HTTP/2, carry a `Content-Security-Policy` that allows no scripts. On the panel's host, an HTML error template ran its scripts on the panel's origin (the production review of v2.4.1 puts that policy in every other error page too).
- **Reloading on a slow disk:** the folders of the sites of `turbo.config` are looked at before taking the global lock, as their certificates and preprocessors already were, so a slow or network disk doesn't hold up every request while `turbo.config` is applied.
- **CGIs at shutdown:** when the 10 s of grace run out, Turbo closes the connections still open, which ends their CGIs with whatever they started, and waits up to 3 s for them; before, without systemd, they went on after Turbo.
- **HSTS of the panel without its certificate:** once **Panel certificate** is deleted (`cfgPC a=0`), a request on a connection still open, or on a resumed TLS session, no longer sets `Strict-Transport-Security` again for a year, leaving the browser without a way back to the panel's host.
- **Denied IPs during a reload:** while `turbo.config` is applied, the denied IPs in use stay denied, and the file's list replaces them at once; before, they were off for a moment, and a long list cost O(n²) with every request held.
- **Certbot:** an attempt keeps the ACME account of the previous one (with a new account each time, the limit of Let's Encrypt, 10 new accounts per IP every 3 hours, refused the next sites issued in a row), and a hook that keeps Certbot's output open no longer holds that attempt, and every later one, until a restart.
- **Changing the sites directory (`setM`):** a directory whose sites can't be listed is refused before anything changes (400 "Sites directory can't be read"); before, it left the server without sites until `M` was set back.
- **Headers that only differ in case:** from the panel, one replaces the other of the site; before, both stayed, and each response carried either value.
- **Lists of `turbo.config`:** the date of a denied IP may be a JSON integer, and an entry of `@`, `_` or `#` that can't be used is logged; before, they were skipped without a word.
- **`TURBO_USER`:** the panel warns at startup while the password is `Admin`, whatever the user (before, only with `Turbo`).
- **`{REWRITE_COMPLEMENT}`:** a `?` of the path (`%3F`) stays in it, encoded again; before, the path was cut there.
- **Upgrading from v2.3.rc3:** the rewrite sources are decoded once each, always with the same result (one with `%25` could be decoded twice, depending on the order of a map).
- **Copies of `turbo.config`:** two saves within the same second keep both copies (the second with `-2`).
- **Limit of the headers (`MHB`) after a POST:** the empty lines that a client may send after the body no longer count as the end of the next request's headers, which let one up to the size of the read buffer through.
- **Password hash (`PH`):** a salt or a key of more than 64 bytes isn't accepted; a huge one, written by hand, made every failed login cost minutes of CPU.
- **Logs:** in `turbo.visits`, a field with a C1 control character, a Unicode line separator or invalid UTF-8 is written quoted and escaped, as one with an ASCII control character; and if a CGI can't go in a Job Object on Windows, it is logged (once).
- **The panel's texts:** the last ones in Spanish are in English (**Default**, **MIME type:**, **Help**, **Panel certificate**, **Signing in**), and a denied IP removed by giving it a past date disappears from the panel's list by the server's answer, as intended.

#### Breaking changes
- **A site whose folder is deleted stays in `turbo.config`:** its settings are kept for when the folder comes back, also after a restart. To remove it, delete it from the panel (`delSite` now also forgets a site without its folder, deleting no folder) or from `turbo.config`. A site or subdomain whose settings are kept can't be created from the panel until it is deleted there.
- **No scripts in the errors before the request is read:** an HTML error template with scripts doesn't run them in the errors of 400, 414, 431 and 501 that Turbo answers before reading the whole request, on any host.
- **What a CGI gets:** the request headers with `_` in their name don't reach it, as in Apache (behind a proxy, `X_Forwarded_For` from the client became the same `HTTP_X_FORWARDED_FOR` as the proxy's `X-Forwarded-For`, and won as often as not); and `HTTP_HOST` and `SERVER_NAME` carry the host as it chose the site: in lower case, without a final dot, with its port only if it is a number. Redirections take its port from it too.
- **An IPv6 denied IP denies its /64,** the client that the rate limits count (its addresses change by themselves), and the panel doesn't accept one of the administrator's own /64 ("Current IP").
- **A request whose target doesn't start with `/`** (an opaque one, such as `x:@evil.test`, or `*` outside `OPTIONS`) gets 400; before, it went after the host of a redirection.
- **`TURBO_USER` of more than 24 characters, or with control characters:** Turbo doesn't start, as with an empty one (it is saved as `U`, and `turbo.config` was refused once the variable was unset).
- **Failed TLS handshakes in the log:** they are counted and logged at most once a minute, with the count and the last one, instead of one line each, which let anyone fill the log.

## v2.4

The first release after v2.3.rc3, the commit "v2.4." `57cbb3c` of `main`. It brings together five stages of work, none of them released on its own: they are listed below, newest first, with their changes. Every stage applies when upgrading from v2.3.rc3.

### Stage 5: second review

#### New
- **Continuous integration:** `.github/workflows/ci.yml` runs the checks of the README on GitHub Actions on every push and pull request: formatting, `vet`, `staticcheck`, `govulncheck`, `gosec`, `regenerate -check`, the tests on Linux (with and without `-race`) and on Windows, the real-ports test, 15 s of fuzzing per target and the cross-compilation. Releases are still built by hand with `release.sh`.
- **Version at startup:** the first line Turbo writes says its version, the commit it was built from and the Go version (`msg=Starting … version=v2.4 commit=<hash> go=go1.26.10`), so you can tell whether a security advisory applies. `release.sh` sets the version; a binary built from the source says `version=development`.

#### Fixes
- **Changing the sites directory (`setM`):** the `turbo.config` of the new directory is always read (one with the same date as the one in use was skipped, leaving the sites without preprocessors, HTTPS or rewrites: PHP was served as text); the current password is checked before anything of the new directory is read; the same directory written another way is "no change"; going back to the start directory no longer bounces to where its pointer says; and a periodic reload that is running finishes before the change, so it can't add the old directory's sites to the new one.
- **Saving with the sites directory in the working directory:** with `M` set to `{TURBO_CURRENT_DIR}` (the default) or to the start directory written another way (`.`, a link, `\` instead of `/`), **Save configuration** replaced `turbo.config` with a pointer to itself, losing the sites, the credentials and `PA` on the next reload or start. Directories are now compared as folders, the pointer is never written over the directory it points to, and a whole `turbo.config` is copied to `turbo.config.<date>.bak` before a pointer takes its place. `M` is saved as written (with `{TURBO_CURRENT_DIR}`).
- **Settings of `turbo.config` that can't be applied:** every global or site setting that is discarded on load is logged with its key and the reason (before, they silently fell back to their defaults), but not `R` and `W` off in a subdomain, which every version writes there; JSON integers are accepted where a number is expected (`"MBB": 5242880`, `"S": 1`), and a `"C"` key in `.` no longer saves the configuration halfway through loading it.
- **Saving no longer undoes later changes:** after **Save configuration**, the periodic check (every 30 s) took the saved file for an edit and applied it again, undoing what was changed in between, the new password included. Now only an edit made outside Turbo is applied.
- **Safer `turbo.config` writes:** the temporary file has a name of its own, created anew (a `turbo.config.tmp` already there is neither overwritten nor followed), and on Linux and macOS the folder is synced after the rename, so the new file survives a power cut.
- **`turbo.config` in a fixed order:** sites, subdomains, rewrites, MIME types, headers, preprocessors, aliases, character replacements, denied IPs, code responses and the settings of `!` are written sorted by key (indexes keep their position), so two saves without changes give the same file and a diff shows only what changed; the panel's `sites`, `subdomains` and `subdomainData` answers come in the same order. Before, the order changed with every save.
- **Certbot e-mail:** `cfgE` decoded its value a second time, so `a+b@x.com` became `a b@x.com` and was refused; now it is saved as it arrives. `cfgE` and the `z` of `cfgC` check the e-mail the same way, and now also refuse a second `@`, an empty name before it and a leading `-`.
- **Forms with files:** the 1,000 parts of a multipart form now hold for file parts too (their headers stopped a form at about 500 files).
- **HTTP/2 `RST_STREAM` limit:** only resets that cancel an open stream count, and the limit is 4 times the concurrent streams (200 per second): a browser that cancels everything in progress twice in a second no longer gets its connection closed (the limit was 50, counting resets of finished streams).
- **Responses without the template:** plain HTTP sent to the HTTPS port and an unknown `Expect` now get the error template, with `Server` and `nosniff` (they got Go's fixed text), and a `Trailer: Server` declared by a CGI no longer adds a second `Server` at the end of the response.
- **HTTP/1 header limit:** `MHB` is exact for every request of a keep-alive or pipelined connection too (after the first one, up to 4,096 more bytes were accepted).
- **HTTP/2 header limit:** a single header field larger than `MHB` (a long `Authorization`, for example) gets 431 with the error template on its own stream, and a `:path` longer than `MUB` gets 414; before, either closed the whole connection, with every stream on it.
- **Panel interface:** passwords are typed in hidden fields and the new one is not kept in the page; adding again an IP, a code response, a character replacement or a MIME type (in any case) updates its entry instead of adding a second one, and a denial removed with date 0 leaves the list; a click on the "URIs" word of "Max. size of URIs" opens its dialog; after changing the sites directory the page reloads, so no value of the old one stays; a site, extension or index called `constructor` is shown; and an upload larger than **Max. body size** (`MBB`) says to raise it (each upload replaces the whole folder, so uploading fewer files is no way out).
- **Certificate dialog of the panel:** cancelling any step (e-mail, adapter, confirmation) sends nothing (cancelling the adapter cleared the e-mail and went on); emptying a saved adapter asks whether to go back to webroot and does so (there was no way back from the panel); the dialog of a site no longer shows or saves the values typed for another; and while a certificate is being issued the panel asks for it every 5 seconds, for up to 4 minutes, instead of waiting for a click.
- **Logs:** a log rotated by renaming it (logrotate's `create` mode) is noticed in the next 30-second check, and Turbo writes to the new file (it kept writing to the renamed one); a field with spaces or control characters is quoted, so it doesn't split the line; and a missing preprocessor is logged once a minute per site and extension, not once per request.
- **HTTPS and stopping:** if the HTTPS address can't be opened (or its server stops), nothing is redirected to HTTPS and Turbo tries to open it again every 30 s (sites were redirected to an HTTPS that didn't answer, for good); if the HTTP server stops, the process ends with an error instead of staying alive without serving. `SIGTERM` (what `systemctl stop` sends) and Ctrl+C stop Turbo in order: no new connections, up to 10 s for the requests in progress, the logs closed, and exit code 0.
- **Absolute-form requests:** `GET http://host/x HTTP/1.1`, which HTTP/1.1 servers must accept, is served like `GET /x` (it got 404, and the `W`, `R` and HTTPS redirections built a wrong `Location`).
- **Request host:** the `Host` is taken in lower case, without a final dot and without its port (also `[::1]:80`), so `Example.COM.` is served by `example.com` (it got 404, or the `*` site); internationalized names (`xn--…`) and names with `--` inside a label can be served and created as sites (they were refused).
- **Panel messages:** the panel no longer takes an answer for a missing session because of its content (an error template with `<meta>` or `data-err` stopped it from loading): the server says so with `X-Turbo-Login: required`, and the panel goes back to the login. Panel answers carry `nosniff` and their type (JSON or text). The panel and the login say what happened: network error, no answer in 30 s, 429 or 503 with the seconds to wait, wrong username or password (only then are the fields cleared).
- **CGI errors:** the 504 of a CGI that runs longer than `WT` now reaches the client, over HTTP/1 and HTTP/2 (the connection's own deadline cut it first). A malformed `Status` (`abc`, `099`, `100`, `600`…) answers 500 instead of an empty 200 or a dropped connection, header lines up to 16 KiB (64 KiB in total) are accepted (they were cut at 1 KiB), and every CGI error uses the error template.
- **CGI environment and headers:** `SCRIPT_NAME` is the URL path of the script and `PATH_INFO` is empty (they had the site's folder on disk and the whole path, which applications show in `PHP_SELF` or use for their links). A header set for the site wins over the CGI's header with the same name, instead of both being sent.
- **Windows device names:** `COM0`, `LPT0`, `COM¹`-`COM³`, `LPT¹`-`LPT³`, `CONIN$` and `CONOUT$` are recognized too (also with an extension or a final dot or space): on Windows they are answered with 404, and file upload discards them on every system.
- **Upgrading `turbo.config`:** a schema written as a number (`"^":{"v":2}`) is understood (it was taken for schema 1, multiplying `CIL` and `CIS` by 10 again); when `turbo.config.v1.bak` already exists, the new copy is `turbo.config.v1.<date>.bak` instead of being skipped; an index name with control characters dropped from a v1 file no longer comes back; and the rewrite sources of a v1 file with `%` escapes are decoded, so they keep matching (one that can't be decoded is dropped with a warning).
- **Deleting a root domain:** the settings, certificates and aliases of its subdomains are deleted too (they stayed in memory, the aliases could not be deleted, and a subdomain created again with the same name got them back).
- **Login timing:** a login with the right password and a wrong username takes as long as any other failed login, so the response time no longer tells whether the password alone is right.
- **Password hashing errors:** if the password hash can't be computed (for example, PBKDF2 refused in a FIPS 140 mode), `setP` answers 500 and keeps the password in use, and Turbo does not start with a `TURBO_PASSWORD` it can't hash.
- **Uploading a file and a folder with the same name:** with `a` and `a/b` (or `a/b` and `a`) in the same upload, the later one is discarded and listed, like other names that can't be written; before, the whole upload failed with 500. Where the file system ignores case, so do the names compared.
- **Upload names too long:** a file or folder name longer than 255 bytes (what ext4 and NTFS allow), or a path inside `@` longer than 1,024 bytes, is discarded and listed; before, the whole upload failed with 500.
- **Connection headers written by a CGI:** `Transfer-Encoding`, `Connection`, `Keep-Alive`, `Upgrade` and the like, a `Content-Length` written twice and a header whose value has control characters are dropped from a CGI's answer, as the server frames the response. Before, a `Transfer-Encoding` of the CGI went out next to the server's own, and the client (or a proxy in front) couldn't tell where the response ended; a NUL in a header made the response unreadable.
- **A client that doesn't read a redirect no longer stops the server:** redirects (`W`, `R`, to HTTPS, rewrites to `http(s)://`) and errors decided while the shared settings are read are now written after releasing the global lock, and the file of an ACME challenge is looked at without it. Before, a client that didn't read the answer (for example over HTTP/2) kept the lock, and as soon as a reload or a panel action asked for it, every request of every site waited until `WT` (with `WT` at 0, for ever).
- **HTTP/2 header blocks:** only the first `:path` of a header block longer than `MUB` stays out of the `MHB` budget (it gets 414); another one, also one repeated from the HPACK table, counts like any field, so a header block can't grow without limit.
- **CGI output and processes:** a CGI that is silent for more than 1 s and then writes and ends no longer loses its output (500 "no headers" under load); when its answer can't be used (a wrong `Status`, no headers), its process group is killed and the 500 doesn't wait for it to end; and when `WT` runs out, or the client goes away, after part of the answer was sent, the answer is cut instead of ending as if it were complete.
- **`{REWRITE_COMPLEMENT}`:** in the path of an internal rewrite to a CGI, the request's query reaches `QUERY_STRING` once (it arrived twice); in a redirection, the query it copies from the request keeps its control characters encoded.
- **`setM` to a directory whose `turbo.config` can't be used** (it only points to itself, an invalid schema) is refused before changing anything, as with invalid JSON; before, the directory changed and its sites were served without their preprocessors. A `turbo.config` there that only points to a third directory without a `turbo.config` keeps the settings in use, as a direct `setM` to that one.
- **Saving keeps what it would overwrite:** a `turbo.config` changed outside Turbo since Turbo read or saved it (an edit not reloaded yet, one the reload refused, or one written by a later Turbo) is copied to `turbo.config.<date>.bak` before **Save configuration** replaces it, and a file of a later schema overwritten with `a=overwrite` is kept as `turbo.config.v<schema>.bak`. Before, the edit was lost without a copy. After the first save of a Turbo started without `turbo.config`, the file disappearing keeps the configuration in use, as with one read at start (it brought back the defaults, `PA` empty included).
- **Sessions after the credentials change:** `setM` to a directory whose `turbo.config` has other credentials closes every other session, and a reload of `turbo.config` that changes them closes every session, as `setU` and `setP` do.
- **Messages about `turbo.config`:** the first line says what is wrong (an unusable `PA`, `U` or `PH`, a schema, a file that only points to itself), not always "is not valid JSON"; and nothing of `P` or `PH` is shown, even with escaped characters.
- **Texts the character replacements can't tell apart:** `-,#` and `#,-` are both sent as `-,-,-`, and the server read `#,-` without a word. The panel no longer sends such a text and says why; API §2.1 explains how a client can check it.
- **An extension written with its dot:** `addMIME` with `.css` when `css` already has a MIME answers "MIME unchanged" or "MIME changed", as without the dot (it said "MIME created"). A preprocessor of `turbo.config` that can't be used, written with its dot, is kept under the extension without it, the one requests look up.
- **Certbot's challenge on any site:** a request to `/.well-known/acme-challenge/<token>` whose file is in the site's `@` is served as it is, without rewrites nor the `W`, `R` or HTTPS redirections (a front controller, a rewrite of `/`, or `W` made Certbot's webroot validation fail). Without the file, the request goes on as always.
- **A slow disk no longer holds requests:** the periodic check of the site folders looks at the disk without the global lock (with a slow or network disk, a panel action waiting for the lock stopped every request behind it), saving writes `turbo.config` and its copies without it, and what the settings look at on the disk is looked at before taking it: the executable of `addPreprocessor` and of the preprocessors of `turbo.config`, the certificate files of `cfgC`, `cfgS`, of the sites of `turbo.config` and of the panel, the directory of `setM` and of `M`, and the certificates the renewal checks.
- **CGI processes at a time:** a new setting, `CGP` (**Concurrent CGI processes**), bounds the CGI processes running at once; with `0`, the default, 4 per CPU and at least 16. A request that finds no free slot within 2 s gets 503 with `Retry-After: 2` (before, there was no limit, and a burst of slow scripts could exhaust the server's processes and memory).
- **CGI bodies of unknown length:** a chunked body, or one over HTTP/2 without `Content-Length`, reaches the CGI whole, with `CONTENT_LENGTH`: it is read first, up to `MBB` (in memory up to 1 MiB, and beyond in a temporary file of the system's temporary folder: `/tmp`, or the private one of the systemd unit); larger, 413. Before, a chunked body got 400, and over HTTP/2 the CGI got no `CONTENT_LENGTH` (PHP didn't read the body).
- **Processes left by a CGI:** a CGI runs in a process group of its own (a Job Object on Windows). When `WT` runs out or the client goes away, the whole group is killed, including what the CGI started (only the CGI itself was killed, and a process it left with its output open held the request, its connection and its goroutine until it ended). When the CGI ends normally, the answer goes out with what it wrote, 1 s after its last output at most, and what it left keeps running.
- **Certificate of the panel's own host:** **Panel certificate** (`cfgPC`) has Certbot issue a certificate for the host names in `PA`, validated by HTTP on those hosts (only `/.well-known/acme-challenge/` is answered there) or with a DNS adapter, and the daily renewal renews it too. Its e-mail and adapter are saved as `PCE` and `PCA`.
- **HTTPS for the panel's own host:** the panel uses the certificate placed in the `turbo.panel` folder of the sites directory (`fullchain.pem` and `privkey.pem`, read again when they change) for the names it covers. Over HTTP, a panel request is redirected to HTTPS when a certificate covers its host and HTTPS is open (301, or 308 to keep the method and body of a `POST`); over HTTPS, on a host of `PA`, the panel sends `Strict-Transport-Security: max-age=31536000`. The `turbo.panel` folder is never a site, and nothing in it is served.
- **Error pages on the panel's origin without scripts:** the error template, which the panel's session can change without the password, goes out on the panel's paths, and on every path of a host of `PA`, with a `Content-Security-Policy` that allows no scripts, frames, forms or plugins (its styles and `data:` images still work); the panel's own pages keep theirs. Before, a template with a script ran on the panel's origin, where it could read the panel.
- **Panel files on Windows:** the path of a panel file follows the rules of a site's files (no `..`, `\`, `:` nor device names). Before, a path that started with `/` or had a `\` could read a file of `turbo.dev` outside the panel's folder, and a device name such as `nul` was opened as a file.
- **HTTP/2 `host` field:** a request whose `host` field names another host than `:authority` (the one that chooses the site) gets 400, as RFC 9113 asks; one with the same host is dropped. Before, the other host reached a CGI as its `HTTP_HOST`, over the host that chose the site.
- **Folder rewrites:** a rewrite whose source ends in `/` (`/private/`) also takes the folder named without it (`/private`), which served the folder's index past the rewrite, and on Windows and macOS, whose file systems ignore case, a path in another case (`/PRIVATE/`), which opened the same files.
- **CGI bodies and slots:** the body of every CGI request is read whole, up to `MBB` (in memory up to 1 MiB, in a temporary file beyond), before the CGI takes a `CGP` slot and starts, and it reaches the CGI through a pipe. Before, a client that sent its body slowly held a slot until `RT`, so a few such clients left every other CGI request with 503; and on Windows, a child of the CGI that kept its input open left the temporary file behind. The connection's write deadline for a CGI (`WT` + 2 s) now counts from when the CGI starts, so a body that is slow to arrive still gets its answer.
- **`Content-Length` of a CGI:** one that isn't only digits (`+4`, `-0`) is dropped, as the server frames the response (Go took it as a number but sent it as written).
- **Temporary folder for CGIs:** a CGI inherits `TMPDIR`, `TEMP` and `TMP` from Turbo when they are set. On Windows it got none, and PHP kept uploads and sessions in the Windows folder.
- **Uploading while the site folders are checked:** the periodic check (every 30 s) looks again, holding the lock, at a site whose `@` it didn't find before deactivating it. An upload swaps `@` for the new files between two renames, and a check that fell between them deactivated the site; the next scan of the disk brought it back with the defaults, without its preprocessors, so its scripts were served as text.
- **End of a CGI's output, and Windows:** the 1 s that Turbo keeps reading the output of a CGI that has ended is measured on the monotonic clock (a change of the system time could cut it short), and it no longer stops reading just as the CGI's output starts again. On Windows, when a CGI's answer can't be used, what it left running is killed also if the CGI and its output had already ended: its Job Object was closed by then.
- **A log that can't be opened:** a `turbo.visits` or `turbo.denials` that is there but can't be opened (another owner after a rotation, permissions) is warned about in the log, once while the error lasts. Before, those lines were lost without a word.
- **`.gitignore`:** the binary built in the repository root (`turbo`, `turbo.exe`, `turbo-<system>-<arch>`) is ignored, so it no longer marks a build as modified nor stops `release.sh`.

#### Breaking changes
- **Panel, API and logs in English:** every message of the API and of the logs, and the texts of the panel, are now in English (`"Missing data"`, `"Wrong current password"`, `msg=Starting`…). An API client that compares the messages must use the new ones, listed in the [API specification](./API_SPECIFICATION.md); the HTTP status codes don't change. `setC` confirms overwriting a later `turbo.config` with `a=overwrite` (it was `a=sobrescribir`), the keys of the log lines are English (`site=`, `reason=`, `file=`…), the first line is `msg=Starting server="OKZGN Turbo" version=… commit=… go=…` (`version=development` and `commit=unknown` when they aren't known), and the folders of `hardUpload` and the copy of an invalid `turbo.config` are `@.upload-*`, `@.previous-*` and `turbo.config.invalid.<date>.bak`.
- **CORS headers of the panel:** the API no longer sends `Access-Control-Allow-Origin: default://home` and `Access-Control-Allow-Headers: ok`, left over from a client that no longer exists: no browser has that origin, and the panel works on its own origin.
- **A subdomain serves only its own host:** the subdomain `api` of `example.com` serves `api.example.com`; `x.api.example.com` and deeper levels are served only by a wildcard (`*.api`, or the site's `*`), as the API says. Before, `api` served them too, as if it were `*.api`, and a site with such a host was refused as a coincidence. If you relied on it, add the wildcard subdomain.
- **`PA`, `U` or `PH` that can't be used:** in `turbo.config`, a `PA` that `setPA` would refuse (a port, `;`, more than 32 entries, `null`, an array…) or a `PA` or `PH` with a control character (an escaped `\t`, `\n` or `\r`, which were dropped after the check), a username or a password (`P` without `PH`) out of 1-24 bytes or of another type, or a `PH` that isn't a Turbo hash make the file invalid: Turbo doesn't start and says which key, and a reload or a `setM` to that directory keeps the configuration in use. Before, the panel was left open to every host, or with `Turbo`/`Admin`, without a word.
- **Preprocessors of `turbo.config` that can't be used:** an entry that is not a string, has a wrong extension or a path too long or empty, or names another protocol, is kept with a warning in the log, and its extension answers 500 (before, it disappeared without a word and the files were served as text, their source included). The 128-character limit counts the path as written, without `cgi>`, and a path with `{TURBO_CURRENT_DIR}` is saved as written (once saved, an expanded path could pass the limit and the preprocessor was dropped on the next start).
- **`setM` to a directory without `turbo.config`:** the global settings, the credentials and the lists in use stay, and are written there with the next save (before, the defaults were applied: `PA` empty, so the panel answered everywhere, and the default limits). To a directory with `turbo.config`, the answer says what it changed of `PA` and of the credentials.
- **A `turbo.config` that only points to a directory it can't use:** one that only has `M` and names its own directory (what saving left in its place, see above), a directory that doesn't exist, one without `turbo.config` or with one that can't be used, or one that points back (pointers that point at each other) stops Turbo from starting, with the `.bak` copies to restore; a reload keeps the configuration in use. Before, the defaults were applied, `Turbo`/`Admin` and an open panel included. A valid pointer is followed without applying it first, and a whole `turbo.config` whose `M` names a directory without `turbo.config` keeps its settings there, as `setM` does (it brought back the defaults).
- **Read errors no longer bring the defaults:** a sites folder that can't be read, or a `turbo.config` that is there but can't be read (a broken link, a folder, permissions), stops Turbo from starting (before, it started without sites, with an open panel and `Turbo`/`Admin`); a `turbo.config` that disappears while Turbo runs keeps the configuration in use (before, the defaults were applied); and the error message hides the password hash.
- **`turbo.config` that is not an object:** `null`, an array or a number is treated like invalid JSON (Turbo doesn't start), instead of loading the defaults.
- **`release.sh`:** it refuses a version that is not `vX.Y[.Z…]` with an optional `.rcN` (it names the `dist` folder it empties), and files ignored by git inside `turbo.dev`, which would be embedded in the binaries without being in the repository. It also needs the tag of the version on `HEAD` (create it first: `git tag v2.4 && ./release.sh v2.4`); counts as a change any untracked file, also with `status.showUntrackedFiles=no`, and refuses files marked skip-worktree or assume-unchanged; refuses ignored `.go`, `.s` or `.syso` files and an ignored `go.work`, which the build would use; builds with the Go environment fixed (without the go env file, `GOFLAGS`, `GOEXPERIMENT` or `GOWORK` of whoever runs it); and runs `govulncheck` on each binary before writing `SHA256SUMS` (without it, it warns).
- **`regenerate` (fork tool):** `-patches` needs `-output`; `-output` refuses a folder that is not empty unless an earlier output marked it, and only deletes what it generated; `-update` takes neither and does not go back to an older Go without `-allow-downgrade`; patches are read strictly (line counts of `@@`, context required, at least one patch). Before, `-output .` from the repository root deleted the code of Turbo, and `-patches N` alone overwrote `customNetHttp`. A patch can't create a file that already exists (it replaced it whole, without checking any line), touch Turbo's own `0.*` files, or rename a file (it copied it under the new name and kept the old one).
- **Hosts with other characters:** a `Host` with characters outside `[a-z0-9.-]` (after lower-casing), or a label that starts or ends with `-`, is answered with 404: a wildcard site no longer gets them (a `Host` such as `x&a=1.example.com` reached `{SUBDOMAIN}` in its rewrites). An IP address as `Host` is a single name, served only by the `*` site.
- **`PA` and the panel credentials:** `setPA` refuses `*` inside a list, host wildcards (they never matched) and a value that would leave out the request that sets it; an IPv6 host (`[::1]` or `::1`) now matches `Host: [::1]`, and the answer explains that an IP without `/` is a host. Turbo does not start with `TURBO_USER` or `TURBO_PASSWORD` set but empty (an empty password let anyone in).
- **Character replacements:** they no longer apply to the credentials (`b`, and `a` of `setU`/`setP`), so a password with `-.-` or another token is saved as typed (before, `ab-.-cd` was saved as `ab;cd` and the login failed). Tokens must have at least 2 characters, can't contain a replaced character nor overlap another token, and the fixed ones can't be changed; invalid ones in `turbo.config` are dropped with a warning. They are undone in one pass, longest first, and values read from `turbo.config` are taken literally (with `+`→`plus`, a rewrite `/plusone` became `/+one` on reload).
- **Panel sessions:** over HTTPS the session cookie is `__Host-turbo_session` (another subdomain can't set it, and a cookie with the same name set by one no longer locks the panel); an expired session is refused even before the periodic cleanup, and a request no longer renews a session closed meanwhile; signing out with the cookie needs the panel's own origin (403 otherwise), and the panel waits for the answer; `setU` and `setP` close every other session; and only requests of the panel's origin (or without `Sec-Fetch-Site`) renew the session.
- **Per-IP limit:** `CII` requests per `CIS` window pass, the current one included (the `CII`-th was rejected, and with `CII=1` every new IP got 429 on its first request). The count is cumulative from the IP's first request until `CIL` passes: after `t` ms, `CII` × (⌊`t`/`CIS`⌋ + 1) requests in all, so a quota not used in one window can be used in a later one. The limiters use the monotonic clock, so moving the system clock back no longer blocks clients, and the limiter keeps at most 200,000 IPs: beyond that, new IPs share one count while the known ones keep theirs.
- **Index names:** an index can't end in `.` or a space, have `:`, be a Windows device name or have `~` and a digit, on any system (on Windows, `index.php.` or `INDEX~1.PHT` opened the file under another extension, so it was not preprocessed). The panel refuses them with 400, and `turbo.config` drops them with a warning.
- **Characters Windows doesn't allow in a name:** `<`, `>`, `"`, `|`, `?`, `*` and control characters are refused in an index and discarded from an upload on every system, like the other names Windows treats specially, so a site can be moved between systems (on Windows, one such name made the whole upload fail with 500).
- **A `"^"` that says no schema:** a `turbo.config` with `"^"` whose `"v"` is not a positive integer (`"x"`, `"2.0"`, missing) is treated like invalid JSON: Turbo doesn't start and says why, and a reload keeps the configuration in use. Before, it was taken for schema 1.
- **`hardUpload` all or nothing:** the files are written to a folder next to `@` that then takes its place at once; a failure, or an upload whose names are all discarded (400 "No valid file"), leaves `@` as it was (before, `@` was emptied first). A site deleted during the upload no longer comes back. Too large is answered with 413 (it was 400) and a malformed body with 400 "Invalid parameters". On Windows, a file of `@` that is open stops the upload (400) instead of being left among the new files.
- **Conditions between limits always checked:** `CIS`/`CII` ≤ 66, `CII` ≤ `CIS` and `RHT` ≤ `RT`/2 are checked whichever setting changes (before, `setCIS` and `setRT` could break them) and compared exactly; a `turbo.config` that doesn't meet them loads with `CII` or `RHT` back to their defaults, with a warning.
- **The current password (`b`) counts as a login:** a wrong `b` in any `set<KEY>` counts towards the 5 failed logins of the IP, and while the IP is blocked, `set<KEY>` gets 429 with `Retry-After`, like the login, without checking the password.
- **No `turbo.config` in the repository root:** the example moves to `testdata/config/v2-example.json`, and `.gitignore` covers `turbo.config` and its copies, certificates (`*.pem`, `turbo.certificates/`, `turbo.panel/`) and the logs, so running Turbo in the root, saving or issuing a certificate no longer leaves the username, the password hash or a private key ready to be committed. A clone run in its root starts with the defaults.
- **Reserved names, shared keys and aliases:** no site (nor subdomain of it) can be called `turbo.dev`, `turbo.panel`, `turbo.certificates`, `turbo.config`, `turbo.visits` or `turbo.denials`, the folders and files Turbo keeps in the sites directory (a site `turbo.config` replaced the configuration with a folder, and Turbo couldn't start again; one `turbo.dev` shared the panel's customization). The site `c.a.b` and the subdomain `c` of `a.b` can't both exist: they shared their settings, and deleting one removed the other's; from `turbo.config` or the disk, the first in order stays, with a warning. An alias can't be the host of a site (it hid the site); on load, the site wins and the alias is dropped with a warning, and the panel refuses a site with the host of an alias.
- **Rewrite keywords:** they are encoded for where they go in the target (in the path, segment by segment, keeping `/`; in the query, as a value), and `{FIRST_REQUEST}`, `{DIR}`, `{FILE}` and `{EXT}` come from the decoded path. Before, all were encoded as query values: `{REWRITE_COMPLEMENT}` in a path gave `/new/a%2Fb` (404), and `a%20b` became `a%2520b`. `{REWRITE_COMPLEMENT}` in the path now takes only the path, and the request's query is added to the target's. Unknown keywords are refused (from `turbo.config`, the rewrite is dropped with a warning). An `http(s)://` target needs a host: `https://` alone, which redirected wherever the path said, is refused, a keyword that gives no host answers 500, and `HTTPS://` is accepted like `https://`.
- **The current password for dangerous actions:** besides the session, `addPreprocessor` (in `c`, as `b` is the executable), `delPreprocessor` (in `b`), `hardUpload` (in `b`, in the multipart body), `delSite`, and `cfgC a=0` and `cfgPC a=0`, which delete a certificate (in `b`), need the current password, used as it is sent; a wrong one counts as a failed login. With the session alone, a page served on the panel's origin could run any program of the server, delete a site or, deleting a preprocessor, have the source of a site's scripts served as text. The panel asks for it.
- **Reloading `turbo.config` replaces:** when the file changes, what it no longer has stops applying (before, a header, an alias, a preprocessor, a MIME type, a rewrite, a denied IP, a template or a replacement taken out of the file stayed until a restart, and a later save wrote it back), a changed alias target or index order applies (they were ignored), and changes made from the panel and not saved are lost. The reload is applied at once, so no request sees half a configuration, and the certificates in use keep answering. Entries are applied in a fixed order: with `R` and `W` both on, `R`; with `PHP` and `php`, or a header written twice in another case, or an alias in two sites, the first, with a warning; indexes with the same position, by name. Before, these depended on the order of a map.
- **Reference systemd unit:** the binary goes to `/usr/local/bin/turbo`, owned by root (it was in the sites folder, writable by the CGIs), the service gets a private `/tmp` (PHP uploads work) and `turbo.dev` is read-only for it: `turbo.dev` has to exist, owned by root as the steps create it, or the service doesn't start (when it was missing it wasn't read-only, and a CGI could create it and change the panel's pages). The steps add `/etc/turbo/credentials` (`0600`, root) with `TURBO_USER` and `TURBO_PASSWORD`, so the panel never answers with `Turbo`/`Admin`, and `KillMode=mixed` lets the requests in progress end when the service stops (their CGIs were killed at once). Reinstall the unit following its comments. CGIs and Certbot no longer inherit `CAP_NET_BIND_SERVICE` from Turbo, and the Certbot of snap doesn't work with `NoNewPrivileges`: install it with apt or pip. `deploy/systemd-test.sh` follows those steps, and refuses to start over another `turbo.service`, its drop-ins or drop-ins for every service.
- **IPv6 clients counted by their /64:** the per-IP limit and the failed-login limit count all the addresses of an IPv6 /64 as one client (before, each address had its own quota, so one client with a /64 had as many as it wanted). IPv4 addresses, also written as `::ffff:a.b.c.d`, count one by one.
- **Panel over HTTP:** a request to the panel over HTTP, on a host covered by a certificate (the panel's own or a site's) while HTTPS is open, gets a redirection to HTTPS instead of the answer: API clients have to follow it (308 keeps the method and the body) or use `https://`.

### Stage 4: full security and robustness review

#### Fixes
- **Paths stay inside the site:** the requested path is decoded and cleaned, and files are looked up and opened through the site's `@` folder only (`os.Root`), so no path, rewrite or symbolic link reaches a file or a preprocessor outside it. Please read the security advisory.
- **Percent-encoded paths:** `/a%20b.txt` or `/caf%C3%A9.txt` now serve the files `a b.txt` and `café.txt` (they answered 404).
- **`turbo.config` is always valid JSON:** it is written with a JSON encoder and replaced atomically (a temporary file, then a rename), so a failure while saving leaves the previous file. The new file has `0600` permissions and belongs to the user running Turbo; if `turbo.config` is a symbolic link, its target is replaced and the link stays. If the file on disk is not valid JSON when saving, it is first copied to `turbo.config.invalid.<date>.bak`.
- **Concurrency:** some panel actions (adding a site or a subdomain) read shared state without the lock while it could be written, which could stop the process; a slow panel client no longer holds the lock that every request needs; the password hash of `setP` is computed outside the lock; and two sessions can no longer share a key. A certificate is not requested twice at the same time.
- **Redirections and ports:** the redirection to HTTPS goes to the port of `TURBO_HTTPS_ADDR` when it is not 443, and the `W`/`R` redirections keep the port of the `Host`.
- **Keep-alive after a POST:** a connection whose request body was read to the end is kept open (it was closed).
- **Denied IPs in canonical form:** `2001:DB8::1` and `::ffff:192.0.2.1` now match `2001:db8::1` and `192.0.2.1`; the keys of `@` in `turbo.config` are written in that form when it is saved.

#### Breaking changes
- **Request paths:** a path with `..`, `\`, `%00`, control characters, an invalid `%` escape, invalid UTF-8 (`%FF`), an encoded `/` (`%2F`) or `\` (`%5C`) is answered with 404, whether the file exists or not (before, some got 400). An encoded `/` no longer separates folders.
- **Extensions without case:** preprocessors and MIME types match the extension in any case (`.PHP`, `.Php` run as `.php`), on every system, and are saved in lower case (also those read from an old `turbo.config`).
- **Special file names:** a path segment that ends in `.` or a space is answered with 404, and so is a file requested with a trailing `/` (`/x.php/`); on Windows, also a segment with `:` (alternate data streams), a reserved device name (`CON`, `NUL`, `COM1`…) or `~` followed by a digit (8.3 short names, such as `INDEX~1.PHP`). File upload discards those names on every system.
- **Rewrites:** the source of a rewrite is compared with the decoded path, so a source saved with `%` escapes (`/a%20b`) must be saved again decoded (`/a b`). An internal target is decoded too (write a literal `%` as `%25`), and `{REWRITE_COMPLEMENT}` is what follows the source in the decoded path (plus the query).
- **Control characters:** the panel rejects any value with control characters with 400 "Control characters not allowed", and invalid UTF-8 with "Invalid UTF-8 text". Response templates may still have tabs and line breaks. Such values in `turbo.config` are discarded on load, with a warning in the log.
- **Invalid `turbo.config`:** Turbo no longer starts with the default settings (and the `Admin` password) when `turbo.config` is not valid JSON or cannot be read. It exits with code 1 and shows the file, the line and column of the error, the line itself and the backups next to it. If the file breaks while Turbo is running, the configuration in use is kept and the same message goes to the log. `setM` refuses a sites folder whose `turbo.config` is invalid.
- **Global request limit:** the server-wide limiter no longer reuses the per-IP settings, which could answer 429 to every client once the whole server reached about 100 requests per second. It has its own setting, `CGL` (requests per second among all clients), **off by default**; above it, new requests get 503 with `Retry-After: 1` and no IP is blocked. Per-IP blocks always last 5 seconds (the longer "persistent" block is gone).
- **Panel host (`PA`):** host entries and networks now combine with AND: with both, a request needs one of the hosts **and** one of the networks (before, either was enough, so from an allowed network the panel answered on the sites' hosts too). A `PA` host that serves a site is refused, and so is a new site, subdomain or alias that would serve a `PA` host. A `turbo.config` with such a `PA` still loads, with a warning, and so does a site folder created on disk for a `PA` host: it is activated, and the log warns that the panel shares its origin. Without a host in `PA` (empty, or networks only), Turbo warns at startup that the panel shares the sites' origin: give it a host of its own (see the README).
- **Failed logins:** after 5 failed logins from the same IP within 10 minutes, logins from that IP get 429 with `Retry-After` (1 minute, then 2, 4… up to 15) without checking the password. Attempts still being checked count towards the 5, so simultaneous attempts beyond them get 429 with `Retry-After: 2`. If the password can't be checked within 2 seconds because too many checks are running, the login (and the current password of `set*`) gets 503 with `Retry-After: 2`. The default credentials stay `Turbo`/`Admin`, and Turbo warns at startup while they are in use.
- **`RHT` and `IT` at 0:** they now use `RT`, as Go does, instead of leaving header reading and idle keep-alive connections without a limit. With `RT` also at 0, there is still no limit.
- **One `Server` header:** every response carries a single `Server: OKZGN Turbo`. A `Server` header set by a site (custom headers) or a CGI is replaced instead of being sent next to Turbo's, and a response whose handler sets `Date` no longer goes out without `Server`.
- **HTTP/2 header limit (`MHB`):** each header field now counts 32 bytes on top of its name and value, as HTTP/2 and Go count it, so with the same `MHB` an HTTP/2 request admits fewer headers than before (a long list of tiny fields no longer fits).
- **`application/x-www-form-urlencoded` forms:** at most 10 MiB, even with a larger `MBB` (they are kept whole in memory). Multipart uploads still go up to `MBB`.
- **Panel API parameters that can't be read:** 400 "Invalid parameters" for a malformed encoding, and 413 when they are too large. Before, the error was ignored and the action ran with whatever had been decoded, or answered "Missing data".
- **`cfgR` and `cfgW`:** they are set at the site's root (`d` empty), where they apply (`cfgR` redirects `www.<site>` to the site); with a subdomain they answer 400. The panel only offers them at the root.
- **`cfgC` in progress:** while a certificate is being issued, `cfgC` answers 202 (it was 400) with the same `"status":"WAIT"` JSON.
- **"Delete SSL" (`cfgC a=0`):** it also deletes a certificate older than 75 days (it answered "No certificate" and left the files).
- **Character replacements in every parameter:** as the API specification says, the replacements of §2.1 (`-,-` for `#` and the rest) are undone in every parameter of the panel API (except the site and subdomain of `hardUpload`, which can't contain those characters), also the response template, the header name, the MIME extension, the alias and the site of `addSite` and `addDenied`.
- **Multipart forms:** at most 1,000 parts, as in Go (it was 10,000). File upload (`hardUpload`), already authenticated, takes up to 9,999 files at once (10,000 parts with the password field) (before, the limit on part headers stopped it at about 500).
- **Login only by `POST /admin:`:** credentials are read only from the body, never from the URL, and the body may be at most 4 KiB (413 otherwise). A `GET`, another method or another path under `/admin:` does not sign in. `/admin:signout:` signs out only by `POST`.

### Stage 3: technical base, documentation and deployment

#### New
- **Updated `net/http`:** `customNetHttp` is now the `net/http` of Go 1.26 plus Turbo's patches, documented in [`customNetHttp/PATCHES.md`](customNetHttp/PATCHES.md). It brings every Go security fix released up to that version. File-serving performance is markedly higher than in v2.3.rc3.
- **Configurable ports:** the `TURBO_HTTP_ADDR` and `TURBO_HTTPS_ADDR` variables change where Turbo listens, for example to run it behind a proxy.
- **Reference systemd unit:** [`deploy/turbo.service`](deploy/turbo.service) runs as an unprivileged user with `CAP_NET_BIND_SERVICE`, logs to the journal and restarts on failure.
- **Messages with level and time:** console messages use `log/slog` (`time=… level=… msg=…`).
- **GUI embedded from `turbo.dev/`:** a single copy of the GUI, embedded with `//go:embed`.
- **Checks before publishing:** the README lists the checks to run by hand before each change or release: formatting, `vet`, `staticcheck`, `govulncheck`, `gosec`, `regenerate -check`, tests, `-race`, fuzzing and cross-compilation.

#### Breaking changes
- **Panic in a handler:** closes the connection, as in Go.
- **`charset`:** error responses say `charset=utf-8`, in lower case.
- **Console message format:** changes; scripts that read the old texts must be adapted.
- **Logs in a fresh copy:** a freshly cloned repository no longer ships `turbo.visits` or `turbo.denials`, so nothing is logged until you create them.
- **`TURBO_HTTP_ADDR` and `TURBO_HTTPS_ADDR`:** an invalid value ends the process.
- **Reference systemd unit:** uses an unprivileged `turbo` user instead of root.
- **Panel API:**
  - `addDenied` rejects with 400 "Current IP" the IP the panel is being used from.
  - `del*` actions without all their parameters respond 400 "Missing data" (previously, an empty 200).
  - `setU` and `setP` with the current value respond 400 "User unchanged" or "Password unchanged".
  - `hardUpload` responds 400 and uploads nothing if it cannot empty `@`. It used to mix new files with the ones it could not delete.
  - "Denied IP" rejects the unspecified address (`0.0.0.0`, `::`).
- **The panel sends its parameters in the request body:** the password no longer appears in the URL or in `turbo.visits`. An API client that puts it in the URL would still leave it in the log.

### Stage 2: functional fixes and hardening

#### New
- **Cookie-based panel session:** `turbo_session` is `HttpOnly`, `SameSite=Strict` and `Secure` over HTTPS, bound to the client IP and expires after 10 minutes of inactivity. The token no longer travels in the URL.
- **Hashed saved password:** **Save configuration** stores the user and a password hash (PBKDF2-HMAC-SHA256). A plain-text password in `turbo.config` is converted.
- **Automatic certificate renewal:** certificates issued by Turbo are renewed when fewer than 30 days remain.
- **Certificates by name:** each name gets its own certificate through SNI.
- **Panel restriction (`PA`):** the panel can be limited to some hosts or networks; empty by default. Host entries compare the `Host` header, which the client chooses, so only CIDR networks limit who gets in.
- **Security headers:** the panel cannot be embedded in an `iframe` and is not cached, and error responses carry `nosniff`.
- **Default index:** new sites come with `index.html` as their index.

#### Breaking changes
- **Limits that were not applied before:** `MUB`, `MHB` and `MBB` really limit the URI, the headers and the body. Check whether you saved values lower than you need.
- **CGI:** the body sent to a CGI is limited to `MBB` and CGI programs have a maximum run time. A failure to start one responds 500 without details.
- **Rate limiter:**
  - responds 429 instead of closing the connection;
  - counts once per request, so the effective limit is about 3 times higher;
  - `CIL` and `CIS` become real milliseconds (the migration multiplies saved values by 10).
- **Panel API:**
  - `b` (the current password) is required in every `set*`;
  - a POST authenticated with the cookie must come from the same origin (403 otherwise); with the `ok` header it does not have to;
  - the token is no longer accepted in the URL.
- **Session cookie:** uses `Path=/`. Turbo removes it from the `Cookie` header before starting a CGI.
- **Preprocessors:** if the executable is missing, they respond 500 instead of serving the file as is.
- **Rewrites and indexes:**
  - a rewrite to `http(s)://` with a path or query redirects to that exact target; if it is only a domain, the original URI is appended;
  - indexes are tried in the order they were added.
- **File upload:** deletes all of `@`, subfolders included, and reports the discarded names.
- **HTTPS:**
  - the connection is rejected for names without a certificate, without SNI or by IP;
  - an alias needs a certificate that covers its name.
- **Port 80:** the process exits if it cannot open it, so systemd notices and restarts it.
- **`turbo.certificates`:** Certbot works in one folder per site.

### Stage 1: immediate stability and security

#### Fixes
- **Hangs and crashes:**
  - some configuration values no longer hang the server or end the process;
  - there are no more unsynchronized concurrent accesses that could abort it;
  - a slow download no longer leaves the other clients without an answer.
- **TLS:** the minimum version is TLS 1.2.
- **Denied IPs:** "Denied IP" really blocks.
- **Certbot:** only runs when the administrator asks for it.
- **HTTPS redirection:** only sites that have it enabled are redirected.
- **Go patches:** Go's HTTP server security fixes are ported to `customNetHttp` (chunked, Range, CONNECT and HTTP/2).
- **Binaries:** published static (the Linux one works regardless of the glibc version), built with the latest Go patch and tagged on the exact commit.

#### Breaking changes
- **TLS:** TLS 1.0, TLS 1.1, 3DES and RSA key exchange are rejected. With Go 1.26, certificates with a negative serial number and RSA keys under 1024 bits are rejected too, and ML-KEM is enabled.
- **HTTPS redirection:** hosts without a configured site are no longer redirected to HTTPS, and a host is redirected only when its site has HTTPS on and a certificate covers the host; otherwise it is served over HTTP.
- **"Denied IP":** blocks. `"@"` only stores IPs denied by hand, not the rate limiter's temporary marks.
- **Certbot:**
  - no longer starts on its own;
  - "Delete SSL" without a certificate does nothing;
  - an email is required;
  - only `dns-<provider>` adapters are accepted.
- **Rewrites:** those that do not start with `/`, `http://` or `https://` are rejected. Those already in `turbo.config` are dropped on load, with a warning in the log.
- **Logs:** `turbo.visits` and `turbo.denials` are detected by the periodic check, so logging starts up to 30 s after the file is created.
